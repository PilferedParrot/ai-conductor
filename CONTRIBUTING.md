# Contributing

PilferedParrot welcomes focused bug reports and pull requests. Before starting a large change,
open an issue describing the use case and proposed trust-boundary impact.

## Development checks

Use Python 3.12 or later on Linux. Bubblewrap is required for the shell-isolation tests.

```bash
cp config.example.json config.json
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
python3 -m compileall -q pilferedparrot tests
```

Keep machine paths, credentials, provider output, chat data, and generated bytecode out of commits.
Update tests and documentation with behavioral changes. Keep changes compatible with the local-only
security model described in `SECURITY.md`.

### Browser end-to-end tests

The browser suite uses Playwright's headless Chromium against an ephemeral loopback server. Its
fixture writes configuration, chat state, model state, and the run ledger under a temporary
directory, and replaces provider dispatch with an in-process fake. It needs no provider credentials
and must not make external network requests.

Install the pinned Python package and its Chromium/system dependencies:

```bash
python3 -m venv /tmp/pilferedparrot-playwright
/tmp/pilferedparrot-playwright/bin/pip install -r requirements-browser.txt
/tmp/pilferedparrot-playwright/bin/python -m playwright install --with-deps chromium
```

Run precisely the browser suite, headlessly as CI does:

```bash
PYTHONDONTWRITEBYTECODE=1 PILFEREDPARROT_REQUIRE_PLAYWRIGHT=1 \
  /tmp/pilferedparrot-playwright/bin/python -m unittest discover \
  -s tests -p 'test_browser_e2e.py' -v
```

Without `PILFEREDPARROT_REQUIRE_PLAYWRIGHT=1`, normal test discovery skips these tests when the
optional Playwright package is absent. CI installs Chromium and sets the variable so a missing
browser dependency fails instead of silently skipping browser coverage.

## Pull requests

- Explain the user-visible behavior and security implications.
- Keep commits scoped and use an identity you are comfortable publishing.
- Confirm that no generated files or private data appear anywhere in the submitted history.
- Do not weaken provider sandboxing, loopback checks, or CSRF checks without explicit discussion.
- Do not add automatic routing, delegation, second-model review, or repeated prompt wrappers as a
  convenience feature; those change the product's token and trust model.
