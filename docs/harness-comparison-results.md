# Harness comparison pilot — 2026-09-06

All six contained Codex runs passed the fixed acceptance checks and independent lead artifact review.
There were no provider failures, retries, escalations or model substitutions. This validates the
bounded workflow on these fixtures; it does not establish net monetary or subscription savings.

## Observations

Direct arms requested Sol/high; delegated arms requested Luna/medium through the real product
Harness and Codex CLI 0.153.4. Each arm used a fresh parent, its own copied project, the same
provider permission settings, and no inherited conversation. The worker condition created a
linked child session. Requested model/effort were explicit; the CLI stream omitted runtime model
and effort confirmation, so those fields remain unknown.

Pair 1 implements trimmed, stable, case-preserving label deduplication. Pair 2 supplies a regression
test distinguishing zero from None; its checker requires failure on the seeded defect and success
on a supplied correction. Pair 3 shares positive-integer validation while retaining behavior.
The run order was direct/delegated, delegated/direct, direct/delegated across the three pairs.

The lead checked source/checker hashes, inspected every submitted artifact, reran all six unchanged
acceptance commands, and recorded artifact digests in the product. Checker time was measured
separately (approximately 0.02–0.09 seconds per arm); lead review was estimated at 30 seconds per
artifact. Artifact rework was zero; experiment setup, briefing and evidence repair are not fully
attributed. Source and manifest files outside the permitted edits remained unchanged; Python
checks generated bytecode only in the disposable projects. The shared fixtures retain their seeded
starting state. Raw provider output, paths, session identifiers and app stores remain private.

## Limits and protocol deviation

Prospective estimates were recorded as 20 direct effort points versus 1 briefing + 4 execution +
2 verification + 1 expected rework for delegation. These were illustrative, uncalibrated estimates.
Their arithmetic exercised routing, but does not validate its economic prediction. The tiny
convenience sample, cache differences, shared local CLI instructions and missing complete overhead
prevent a savings or model-superiority conclusion. API-equivalent cost and subscription consumption
remain unknown. Delegation used more input tokens on two of the three pairs.

The experiment runner initially recorded checker-only acceptance before lead review, then removed
those review events. Original verdict snapshots and the corrected pre-review state were retained
privately. The lead subsequently inspected all six artifacts and reran the unchanged checkers before
recording fresh acceptance through the product. This is a disclosed pilot deviation, not a clean
preregistered audit trail; no failed provider runs were hidden or rerun.

UI validation alongside the pilot identified the need for readable statuses, explicit next actions
and a direct path from a completed worker to parent review. These changes have browser coverage,
including the exhausted retry limit and narrow layouts.
